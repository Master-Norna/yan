# 言

一个本地运行、零依赖的聊天前端，接 OpenAI 兼容接口，也接 Anthropic 的 Messages API，界面取清简纸墨之意。同一段对话，绑上工作目录即是「行 · 执事」——一个只做代码工作的轻量 Agent，在那个目录里检索、读写、修改文件并执行指令；不绑目录即是「言 · 对谈」——照常聊，需要产出表格、文档、PDF 之类的文件时，同一套工具落在本机的「卷宗」目录里。

> 清简为骨，纸墨为意。长问慢答，尽付纸墨；言毕，即行。

- **本地**：对话、模型配置与草稿存于浏览器本地存储，附件原件存于 IndexedDB，不经任何云端
- **零依赖**：仅需 Node.js 18 或更高版本，无需安装 npm 包，所有前端库随项目本地分发，不加载在线资源
- **可控**：本机桥接仅监听 `127.0.0.1`；执事指令逐条可见、默认需经确认；备份不含 API Key

## 快速开始

双击 `start.cmd`，或在项目目录运行：

```powershell
npm start
```

浏览器会打开 `http://127.0.0.1:8787`。首次使用时，在「设置 → 模型」中填写显示名称、模型 ID、Base URL 与 API Key，并设置用量限制；项目不会读取或内置开发者电脑上的任何配置。可以添加多个接口并切换默认模型；每个模型可选「接口」是 OpenAI 兼容（chat/completions）还是 Anthropic（Messages API），Base URL 带 anthropic.com 的不选也认。接 Anthropic 时页面与桥接内部仍是 OpenAI 的格式，只在最外面换一层：请求换成 Messages API 的（system 单列、工具结果并进 user、工具定义换成 input_schema、思考档位换算成思考预算，开了思考时不传 temperature），事件流换回 OpenAI 风格的分块（思考块带签名回传给下一轮，带工具调用的那一轮 Anthropic 要求如此）；图片与 PDF 原件照送，别的文件只留一行说明。

`start.cmd` 打开的 CMD 窗口即本机桥接进程，必须保持开启；关闭后已加载的页面暂时仍在，但刷新、模型转发、联网与执事都会停止。浏览器开了、页面却报「本机桥接已停止」时，先看这个窗口：桥接退出会停在那里并打出原因（端口被占、缺 node 等），不会一闪而过。

### 在 VS Code 内使用

1. 通过「终端 → 运行任务」执行「言：启动模型桥接」，并保持该任务终端开启。
2. 按 `Ctrl+Shift+P`，运行「Simple Browser: Show」，输入 `http://127.0.0.1:8787`。
3. 在「设置 → 模型」中填写配置；可先点「获取列表」，再点「测试连接」与「测试联网」。

也可以直接预览 `Lumen Chat.dc.html`（用的是仓库里的 `support.js` / `app.css`；改过 `src/` 或 `styles/` 后先 `npm run build`，桥接启动时也会自动产出）。页面会连接 `127.0.0.1:8787`；若先开页面、后启动桥接，下一次获取模型、测试或发送时会自动重连。若模型接口本身开放浏览器跨域访问，也可以不启动桥接而直接对话。本机联网需要桥接；执事接口还会校验页面来源，需从桥接地址或 VS Code Webview 打开，`file://` 页面不能执行本机指令，也拿不到桥接的会话令牌、用不了服务端预设的模型（自己填 Key 的模型不受影响）。系统浏览器与 VS Code 预览扩展可能使用不同的浏览器存储，模型配置需分别填写或通过备份导入。

### 环境变量

- `YAN_PORT`：更换桥接端口，默认 `8787`
- `YAN_API_CONFIG`：开发调试时显式指向一份配置文件（`Base URL:` / `Model:` / `API Key:` 各一行，可加一行 `API: anthropic`）；普通启动不会自动读取任何外部配置
- `YAN_DEBUG=1`：把每个请求与异常断开的连接打到控制台，页面报「Failed to fetch」「本机桥接已停止」时用它看请求到底有没有到桥接

## 代码结构

零依赖、无转译：源码分成多段，桥接在请求 `/support.js` 与 `/app.css` 时按文件名顺序即时拼接（ETag 取各段的大小与修改时间），改一段刷新即生效；`node build.js` 产出仓库里的 `support.js` 与 `app.css` 供 `file://` 直接打开。

| 目录 / 文件 | 内容 |
| --- | --- |
| `src/` | 页面脚本，按领域分段（状态与存储、对话数据、Markdown 与图表、渲染、行迹时间线、旁注、记忆、文件与卷宗、对话引擎、工具执行、接口、设置），拼进同一个闭包。数据模型（Store / Conversation / Message / Step / Profile…）以 JSDoc typedef 写在 `00-state.js` 顶部，`types.d.ts` 是给类型检查用的全局声明（随项目分发的库、宽松的 DOM），运行时不加载 |
| `styles/` | 样式，按层次分段（基础与主题、布局、欢迎页、对话、正文内容、文件、输入区、设置、行迹、组件、动效与响应式、纸墨皮肤）；顺序即层叠顺序 |
| `prompts/` | 内置提示词与工具说明，见其 README |
| `server.js` · `server/work.js` | 本机桥接：转发、联网、静态与拼接；执事接口（目录、指令、文件、检索、目录选择框）与卷宗目录接口（列、收、取、删） |
| `test/` | `npm test` 先跑 `test/unit/`（Node 自带的 `node --test`，把 `src/` 拼起来在 Node 里测纯函数：工具参数救治、流式分段、diff 计数、余墨、思考档位、只读指令、输出裁行……几百毫秒跑完），再跑端到端：起假模型接口、测试桥接与无头 Edge / Chrome，逐个跑用例（对谈、执事、言行合一与卷宗、差遣、旁注、记忆、余墨与历史、表单、健壮性、桥接安全）；面向 Windows，其他平台未做适配 |
| `build.js` | 拼接产出；`npm run format` 用 Prettier 统一格式，`npm run check` 用 `tsc --checkJs`（按 `jsconfig.json`）做类型检查——两者都经 npx 临时取用，只在开发时，不进运行时、不进依赖 |

## 本机桥接

`server.js` 是一个单文件的本机进程：加载页面、转发模型请求、代模型执行联网检索与网页读取（拒绝访问本机与内网地址，IPv6 字面量与 IPv4 映射地址同样按此判；正文边读边截，最多只收 3 MB），以及执事模式的指令与文件操作。静态文件带 `ETag` 校验，改动后刷新即生效；控制台不会显示 API Key。

桥接每次启动随机生成一枚会话令牌，只发给本站页面与 VS Code Webview；用服务端预设模型（`YAN_API_CONFIG`）转发时须带上它，别的本地页面借不到这份 Key 的额度。一次请求最多带 128 件工具定义，超过明确报错而不是悄悄截掉后面的。

## 对谈

**会话与输入**

- 多会话、新建与删除；侧栏可按标题与正文搜索，支持置顶、重命名（侧栏双击或点击对话标题）；侧栏收起与否记在本机，刷新后照旧；停在哪一页（正看的对话、卷宗）也记着，刷新回到原处
- 头一问发出时就自动请模型拟题，与作答并行——侧栏里立刻是个像样的名字（通用设置可关闭；手动改过的标题不会被覆盖）；拟题请求偶然失败不会把这段对话标成已拟题，那一答收尾时再试（这时带上答）
- 新对话与每段旧对话分别保存未发送草稿，文字与待发附件在刷新、切换对话或打开卷宗后恢复
- 右下角的「上下文 ≈ n」实时估算下一问会送出多少 token（系统提示、工具定义、上次压缩以来的历史与行迹摘要、正在输入的草稿、案上待发的附件与引文），随输入与生成翻动，过重转印色；点它可「压缩前文」——请模型把此前往来压成一份摘要（目标、事实、决定、改过的文件、待办），记在分隔线上、点开可读，压缩过的前文在页面上折起（分隔线上可展开），此后的每一问只带摘要与之后的消息；设置里可定阈值让它在一答写毕后自动压缩。摘要先在外面生成，成了才一次性落成分隔：压缩期间接着发消息不会失忆，中途关页面也不会留下半成品分隔把历史截掉。模型高级配置里填了「上下文窗口」，计数就按 `n / 窗口` 显示、底下一道细线按比例走，用到七成半即转印色。每一答末尾的「耗墨 n」是这一答各轮请求的用量之和（含帮手）
- 下一问送出的历史里，每一答附一行「行迹」摘要：读过、改过哪些文件，请示的答复，差遣的回报，以及检索到的前三条标题与链接、翻阅过的网页——模型不必从头再探；工具结果原文与思绪不重放
- 对话多于一问时，右侧有一条按问的导航条：一问一道短横，当前所在加长转印色，悬停露出各问首句，点一下回到那一问
- 引用追问：在回复或自己的话里划选一段文字，浮出「引用」，点击即作为引文带进输入框（可 ✕ 去掉、Esc 去掉、随草稿保存）；发出后显示在问题上方，点击回到出处；送给模型时以 `>` 引块置于问题之前
- 旁注：在回复里划选一段，选「旁注」，右侧开一条附在这一处的小对话——它读得到正文（到所注消息为止，尊重压缩），正文永远读不到它；只带查阅类工具（检索、翻网页、翻文档、翻记忆与旧谈），不动文件、不请示、不差遣，各步画在旁注回复自己的行迹里。正文还在生成时也可以就上面的回复开旁注、复制；旁注生成中往上翻就不再拉回底部。所注消息的元信息行标「注」（几条就标「注 n」），对话标题下标「旁注 n」。回复动作里的「旁注」、标题下的「旁注 n」打开的是**目录页**：这段对话里的旁注一条一行（所注的一段、落在第几答、几问、最近动笔），点哪条开哪条；顶上的「＋」另起一条——正文里划着一段就注在那一段上，没划就是就整条回复而谈，同一条回复上可以起几条。看某一条时面板顶上列所注的一段（就整条回复起的没有范围可言，不列），‹ › 在各条间切换、左下角「‹ 目录」回目录、「阔」铺满整页、「删」移除；旁注里的问可编辑重问，答可重新生成——旁注不留版本，改了就是改了。旁注跟着它所注的那一问一答走：换到另一条分支，注在被换下去的那几条上的旁注便不在眼前（仍在册，换回来就回来）。落点记的是消息 id、划选的文字与它在正文里第几次出现——同一条回复里同样的词出现两次、注的是第二处，重画后仍落在第二处；每次从干净的正文重新找：两条旁注划的段落有重叠也各自落得上，划选跨过了已有旁注的脚注号也不碍事
- 尚未接入模型时，欢迎页直接给出引导；「设置 → 关于」列出数据边界、键与操作和开源致谢

**生成与版本**

- 发送键是一方印：未落墨时是空印，有字时蘸满印色，悬停微转像要落印，印文「寄」；生成中印文换「止」、外圈一道墨环流转不息，点它即停
- 流式回复按「落墨」节奏匀速写出（积压越多写得越快，最多滞后零点几秒），新字带短暂渐显、末尾跟一支笔尖光标；回复元信息里的小印章在书写时呼吸、写完时盖下。「设置 → 个性化」可将界面动效设为开启、随系统或关闭
- 作答途中也能再说一句：输入框里写了字，印由「止」变「寄」，寄出的是**补言**——先落在行迹里它到达的那一刻（一步「补言 · 待寄」），到下一回合的边界（工具结果交回、模型再开口之前）递给模型；这一答若已在收尾、不再有下一回合，就在落笔后作为新的一问接着送；中途按了停则放回输入框。案上空着时按印才是停止
- 停止生成、重答、失败重试、复制；切换或新建对话不会打断已有请求，多段对话可在后台同时生成，侧栏显示运行、等待确认与未读状态；刷新或网络中断时保留已生成正文，并提供「继续生成」
- 生成中的跟随：往下滚到离底不远就算到底、开始跟随（内容一直在长，硬要滚到最后一像素常常追不上），往上滚离底超过 80px 才算离开；跟着的时候内容不论因何长高（工具输出、图表成图、图片载入、块的开合）都贴着底，不只靠流式的每一帧
- 分叉：编辑问题或重答不再截断，被换下的那段整段留作一个版本，消息旁以「‹ 2/2 ›」切换；版本可以嵌套，切换时当前这条停在原位；备份格式随之升到 v4（旧备份可直接导入）
- 生成时向上翻阅会出现「回到最新」浮标；长对话按可见消息锚点保存滚动位置，关闭设置、切换对话以及异步图表完成后回到原阅读位置
- 思考模型的 `reasoning_content`，以及部分接口直接写在正文开头的 `<think>…</think>`，都显示在「思绪」折叠区；流式推理时默认展开、正文出现后自动收起，手动开合时尊重用户选择
- 自动开合的规矩（思绪、行迹、帮手卡片同一套）：一答只开一次、收一次——开始时摊开，整答写完才收，中间模型说话的间隙不来回翻；收之前停一拍让勾打上；正往上翻着读这一块的人不替他收，留给他自己；用户亲手开合过的一律不动
- 消息列表按 id 增量同步：只插入、替换或移除有变化的那几条，其余节点（含已画好的图表与 HTML 沙箱）原样保留；明暗、印色或字体变化时图表就地换色

**呈现**

- Markdown 由 marked 解析、DOMPurify 净化：表格、嵌套列表、任务列表、highlight.js 代码高亮、代码块语言标签与复制按钮、KaTeX 公式（`$…$`、`$$…$$`、`\(…\)`、`\[…\]`）
- 页内可视化：```mermaid 渲染流程图 / 时序图 / 结构图，```echarts（ECharts option 的 JSON）渲染数据图表——模型常见的几处失手画之前先扶正：系列指到不存在的坐标轴、坐标轴指到不存在的格子（多图并排最常见）收到最后一个，漏了 type 的按数据形状补；完整的 ```html 代码块在无网络、无父页面权限的隔离沙箱中直接渲染成交互程序。代码尚未写完时先立一个占位框：框里是一道虚痕——与顶栏「余墨」同一笔形，墨未着纸，淡淡地呼吸；每来一行，痕上吸一口朱墨又散去，流停了就只剩呼吸，一眼看得出还在写还是卡住了；框边一点呼吸的墨光，逐帧重画时占位框本身不重建、呼吸不从头来；完成后再挂载；三类作品均可全屏，图形可下载，HTML 可重启、查看源码与另存为文件
- KaTeX、mermaid、ECharts、pdf.js 只在首次用到时按需加载，首屏只带 marked + DOMPurify + highlight.js（约 200 KB）；主题、印色与字体由 `theme-boot.js` 在样式解析前写入，暗色模式开页不会先闪一下米白
- 明暗主题、字体、阅读宽度与印色；纸面带细微纸纹，亮色角落是一圈茶渍，暗色右上挂一轮月晕；切换明暗：亮到暗是「落墨」——三滴墨先后坠下，触纸渗进纸面，墨从落点洇开、墨缘参差，铺满整纸的那一刻纸换成暗色，墨色退去，字迹从中浮出；暗到亮是「天光」——光没有形体，从按下的那一点以柔边漫开，照白整纸后光退去，字迹浮出。墨团与光晕是几张带湍流滤镜的 SVG，开机后闲时各画成一张上了色的位图，动效里只放大位图、再淡出，全程在合成层上（不套遮罩、不动滤镜、不用 View Transitions，240 Hz 的屏上也不掉帧；主题重排那一下藏在墨底下）；关了动效则直接切换。顶栏右侧的三件同一套笔墨：连接状态是一点印泥（静时空心、忙时朱色呼吸、断时转赤），中间一方砚台（亮色时空砚悬一滴墨，暗色时砚里蓄满墨只余一点纸光），右边是余墨的一笔
- 触屏设备上 Enter 只换行、用按钮发送；侧栏在窄屏下以抽屉打开，点空白处收起；页签标题跟随当前对话

## 附件与卷宗

- 点击、拖入或粘贴图片、文本、代码、PDF、Office 等文件；PDF、DOCX、PPTX、XLSX 等会先在浏览器本地提取正文，图片按视觉内容发送，其他二进制文件使用兼容接口的文件内容格式
- 附件原件保存在浏览器 IndexedDB，单件 32 MB、单次最多 10 件共 64 MB，卷宗与附件原件合计 2 GB；收入卷宗的单件 256 MB；PDF 解析器与中文字符映射随项目本地分发
- 「卷宗」：跨对话保存常用文件。桥接在线时卷宗就是本机的一个目录（默认 `~/言/卷宗/`，即当前用户目录下；设置 → 通用 → 卷宗目录可改到任意位置，路径存在浏览器配置里、随请求传给桥接，桥接本身不记状态；环境变量 `YAN_ARCHIVE` 改的是默认值），页面上的卷宗即这个目录的视图：拖入（只认从页面之外拖来的；卷宗里的图、案上的附件在页内拖动不会又收一份）、按「藏」收入的文件落盘到这里，没绑目录的对话里模型写出的成品也在这里；可预览、下载、删除；要随消息送出，从输入框的「＋」里选「卷宗」（网页与脚本文件一律按纯文本在沙箱里给出，不会以本站身份运行）。模型为了做出成品而写的脚本与中间文件放在卷宗里的隐藏目录 `.草稿/<对话id>/`，页面不列它；删除对话时随之清掉，卷宗页顶上也有「草稿 n 处 · 大小 · 清理」。言里一答做出的成品（这一答在卷宗根目录新出或改过的文件）挂在答末的「成品 n 件」卡上，一件一行——类型、文件名、大小，右侧「预览」与「下载」；之后在卷宗里删掉了的，那一行留着但标成「已移出卷宗」、收起两个按钮。「预览」是就地的悬浮预览，不必先下载：图片直接看，PDF 交给浏览器自带的阅读器，CSV / TSV 排成表格，Markdown 渲染，文本与代码按原样，Word / Excel / PPT 在本机抽出正文，网页进与页内交互预览同一个隔离沙箱；卷宗页的每件文件也有这个「预览」。卷宗里的文档（PDF、Office、文本）对言与行的每段对话都可读：模型用 `read_document` 翻阅，用到时才取回并在本机抽正文，设置里可关。对话标题下的「存入卷宗」把整段对话存成 Markdown（含行迹摘要与成品）落到卷宗；没桥接时为下载。直连没桥接时退回浏览器内的版本（原件存 IndexedDB），桥接接通后旧件可一键落盘。按名搜索、按 画 / 文 / 卷 过滤；删除对话不会删掉卷宗中的成品
- 多轮对话只有本轮要回答的那条消息携带附件原件；更早消息里的文本与提取正文改为摘要（超过 3000 字截断），图片与二进制原件改为占位说明。若要让模型再次看到旧图片，可从卷宗重新置于案上
- 本轮的文本附件与提取正文也有个上限：约为模型窗口的一成半（没填窗口按 24k token），超过的只随消息给一行「文件名、字数」，模型要看就用 `read_document` 按页或关键词取，不会把整本书硬塞进提示撑爆窗口；附件入库时顺手记下字数估算，右下角的上下文计数按它算
- 备份导出与导入：导出时可勾选「含附件原件」；导入采用合并策略（按 id 跳过已存在的对话 / 模型 / 卷宗，并合并未冲突的草稿）；备份不含 API Key

## 模型与工具

- 每个模型可设置 system prompt、temperature 与 max_tokens（默认 8192），并**必须**设置独立用量限制，支持 `k`（千）、`m`（百万）、`e`（亿）；右上角「余墨」随用量递减，耗尽后该对话暂停，更换模型或调高上限即可在原处续写。用量在每一答收尾时结算，停止、断网、工具链中途出错也照记（接口没给 usage 的那一轮按估算）；一答开工时先按「提示 + 最大输出」预留额度，几段对话同时开工时后来的看得见先来的已占多少，不会都以为还剩一样多而合计超卖
- 模型选择在发送键旁，菜单底部是思考强度（默认 / 低 / 中 / 高 / 关）：对话中改的只作用于本段，欢迎页改的是新对话默认；OpenAI 系接口发送 `reasoning_effort`，DashScope 兼容模式发送 `enable_thinking` 与 `thinking_budget`，「默认」不带字段。各家认的档位不一样（有的只有 low / medium / xhigh，有的多 minimal 或 max）：模型高级配置里可填「思考档位」，菜单只列这个模型认的几档；没填时用通用的低 / 中 / 高，接口拒绝某档时会从报错里记下它认的档位、把这一问换成最接近的一档重发（选「高」而它只有 xhigh 就用 xhigh），之后菜单与发送键旁的标签都按记下的档位显示
- 工具参数按 JSON 收，模型写得潦草也尽量救回来：裹了代码围栏、结尾多一个逗号、整段被 max_tokens 截断、把参数对象又编码成字符串，都会先修再解析；实在解析不了才算失败，回给模型的话里带上具体的出错位置、这件工具该收的参数与收到的原文，让它一次就能改对
- 工具调用（function calling，可在模型高级配置中关闭）：`search_web` 免 Key 检索（桥接抓取 Bing 国际索引，DuckDuckGo 备用）、`fetch_page` 读取网页正文、`read_document` 按页码或关键词翻阅对话附件与卷宗中的文档；全部合并在「行迹」折叠区，每一步以转圈 / ✓ / × 表示运行、成功与失败；同一轮的重复调用直接复用已有结果（只复用成功的）；同一轮里相邻的只读调用（读文件、搜索、翻网页、翻记忆）并行执行，结果仍按原顺序回传；执行、写入、修改与请示逐个来
- 联网回答结束后从成功的搜索与网页读取步骤生成去重的「出处」卡片，已阅读全文的来源单独标记
- `ask_user`：下一步取决于用户的选择时，模型可弹出一张小表单（最多 8 题、通常 1–3 题，一题一页可前后翻，每题 2–4 个选项，可多选、可自行填写；单选题里选项与自行填写二选一）从输入框上方浮出；对谈与执事都可用，答案随「行迹」摘要带进后续轮次
- 「接口原生联网（实验）」只随请求发送 `enable_search: true`，仅供接口文档明确声明支持的服务使用；它不能替代本机联网
- 内置提示词（通用系统提示、执事工作法、旁注聚焦句、各工具的说明）全部在 [`prompts/`](prompts/README.md) 目录，改完刷新页面即生效；`support.js` 只做拼接

## 言与行：目录决定

言与行不是两个入口，而是一段对话有没有绑工作目录。欢迎页输入框上方的「目录」小签空着，这一纸就是**言 · 对谈**；填了路径（或点「选择…」以系统对话框选取，Windows 上是资源管理器风格的现代对话框，带地址栏与搜索），就是**行 · 执事**。侧栏的一枚印只显示当前的态，改态去目录签。目录可以在对话中途绑上——标题下的「绑定目录」——此后工具与提示词随之而变，历史一字不丢，适合先聊清一个想法、再带着上下文动手；点目录路径可更换或解开，解开即回到言。侧栏历史是一条时间线（置顶 / 今天 / 过去七天 / 更早）：绑了同一目录的对话归在一个带「工」印的组里，组按组内最近动过的那条排（一条有动静，整组靠前），组内按时间；没绑目录的对话按自己的时间散在其间；点组头收起 / 展开（收起时仍露出当前打开的那条），组头右侧的「＋」在该目录另起一纸。

桥接在线时，言与行的文件工具落脚处、作风与确认各不相同：行拿六件（含逐字替换与代码检索），言只拿产出文件所需的四件（run_command / write_file / read_file / list_files）并用短说明，系统提示也轻得多——对谈的每一问都背着这些，多一句都是开销。行落在工作目录，系统提示是执事的工作法（先定位再阅读、先说方案、最小改动、改后验证），会改动状态的指令默认问而后行；言落在卷宗目录，提示只说「用户要可交付的文件时才动用工具，脚本放草稿目录、成品放卷宗根」，指令径直执行、不问（卷宗是模型自己的一方沙地——但 shell 本身并无隔离，指令能做的事不止于目录之内）。直连没桥接时言只是纯聊天。执事是一个只做代码工作的轻量 Agent，六件工具：

- `list_files`：列出目录树（目录以 `/` 结尾，文件后跟字节数）；给 `pattern` 时按 glob 找文件（`*.ts`、`src/**/*.js`），跳过 node_modules、.git 等
- `search_files`：按正则（或原文）在文本文件里逐行检索，返回 `文件:行号:内容`，可限定子目录与 glob；用于定位代码
- `read_file`：读取文本文件，带行号、可按 offset / limit 分段
- `edit_file`：精确替换一段文本，`old` 必须与文件逐字一致且唯一（或显式 `replace_all`），CRLF 文件自动保持换行；**本段对话里没读过或写过的文件不允许编辑**，模型必须对着真实内容改；步骤卡上以前后片段展示改动
- `write_file`：新建或整体重写文件
- `run_command`：在工作目录中执行一条指令（Windows 使用 PowerShell，其他系统使用 sh；输入输出均为 UTF-8，指令经编码传入，不受命令行引号规则影响），返回退出码与输出；默认 120 秒超时，最长 600 秒；cmdlet 出错同样以非零退出码返回，错误文本已还原为纯文字

路径相对工作目录；设置 → 通用 →「文件工具可及范围」默认「全盘」，此时完整的绝对路径可以指向目录之外（系统级配置、别处的资料都读得到，写之前模型会先说明），改成「目录内」则一律拒绝越出（含借符号链接 / junction 越出的情形；列目录与检索不跟进链接，链接以 `@` 标出）；工作目录须是完整限定的绝对路径（Windows 上须带盘符）；执事接口只接受本站页面与 VS Code Webview 的请求，`file://` 预览可对谈但不开放执事；文件系统错误以可读说明返回。系统提示要求模型：先定位再阅读、任务不止一步时先说明方案、修改用最小片段、每次改动后运行或测试验证、不改动任务之外的东西。

指令默认**问而后行**：待确认的指令从输入框上方的「执事请示」条浮出（步骤卡上也完整显示），可点「运行」「跳过」或「径行」（此对话中后续指令不再询问），输入框留空时按 Enter 即运行；只读指令（`git status / log / diff`、`ls`、`Get-Content`、`Select-String` 等，且不含管道、重定向或串联）免确认直接执行，卡片标「只读免确认」。输入框旁的「问而后行 / 径行」可随时切换（只有行才有这一档），欢迎页填了目录后出现的小签决定新对话的默认。等待确认时折叠区自动展开，侧栏对应对话标以「问」。文件工具只经本机桥接执行，浏览器直连模式下不可用。

上一答的行迹会压成一行「［上一答的行迹］…」冠在下一问的开头送给模型（页面上不显示），它才记得自己读过、改过哪些文件，不必每轮从头再探。摘要不接在助手自己的话后面：那样模型会把它学成自己回复的格式，答末照写一行。

执事对话里的「行迹」是一条时间线：模型边做边说的话与各步按先后穿插排列，进行中摊开可看过程，做完自动收起成一行「工作了 n 秒 · n 步 · 改 n 个文件」，只留最后的总结在外，点开可回看全过程；各步默认摊开的只有两种：目录清单（露前 10 行）与修改的 diff（两侧各 10 行），底下一行「展开全部」可看全；指令输出、读取、搜索、检索与翻阅这些有明确行数、往往又长的，默认折起（一答几十次检索，命中全摊开要占一整屏），标题行上有结果与行数，点标题行展开；报错的也折起。运行中摊开、运行完收起是行迹与帮手时间线的定例：整答收尾时行迹一律收起，帮手做完它的小时间线也一并收起。对谈里仍是折起的注脚。每一答的末尾附一行改动摘要「n 个文件已更改 · +增 −减」，点开可见逐文件的行数增减（`edit_file` 按行级 diff 计，`write_file` 新建按全文计、覆盖按新旧行数计），逐轮可查。思绪与各步都有进行中的呼吸点、完成后的勾；后几轮的思绪各在自己的分组里，工具参数还在流式拟定时先显示「正在拟 写入 xxx · n 字」。

**差遣（子 Agent）**：遇到可以自成一段的大块子任务（通读一批文件并归纳、在某个模块里排查一个问题、按已定方案实现独立的一部分），模型可用 `delegate` 差遣一名「帮手」去做。帮手用同一个模型、同一个工作目录、同一套工具（但不再差遣、不请示用户，记忆只读——可 `recall`、查旧谈，不能 `remember` / `forget`）另起一段对话独立跑自己的工具轮次（默认最多 40 轮，设置里可改），做完把最后一轮的回报连同改动摘要作为工具结果交回主模型；帮手看不到主对话，任务说明得把背景、目标、边界与要回报的内容写全。同一轮里可差遣多名帮手，他们并行开工（分派时由主模型保证各自改的文件不重叠；桥接那头同一文件的写入与修改按先后排队，`edit_file` 的读—改—写在锁内完成，`run_command` 期间整个目录的文件写入等它跑完，反之亦然——不同文件照常并行）。页面上每名帮手是行迹里一张带「帮」印、衬淡金的「差遣」卡片（朱色留给印章与删减）：里面是帮手自己的小时间线——每轮的思绪、说的话、各步，与主行迹同一套画法，进行中摊开、最新的思绪与话实时跟着流，做完折成一行「帮手 · n 步」，只留回报在外；帮手工作期间输入框上方常驻一条帮手条（一行一名，写着它正在做的那一步，点一下滚到卡片），行迹标题也显示「帮手「…」· n 步 · 进行中」；指令照样问而后行，改动计入这一答的改动摘要与「改 n 个文件」，用量计入上下文成本，下一问的行迹摘要里也带着它改过的文件。帮手读过的文件不算主模型读过（反之亦然）：谁要改，谁先读。对谈模式在桥接在线时同样可以差遣（帮手带联网与文档工具）。

稳定性边界：一次回答默认最多 80 轮工具调用（帮手另计，默认 40 轮），「设置 → 通用」可改，超出后收回工具、请模型直接收尾；停止生成、页面刷新或连接中断时，运行中与等待确认的步骤一并收束，正在跑的指令连同它起的子进程整棵一起被桥接杀掉（`taskkill /T`），不会在后台继续改文件；每次发送前确认桥接在线与工作目录仍在（被删除时自动重建）。

工具参数按 `prompts/tools.js` 里的 schema 理顺：常见的写法出入自动归位（`file_path` → `path`、`cmd` → `command` 之类的别名，数字与布尔写成了字符串，该是数组的只给了一项，`ask_user` 把单个问题摊在顶层），理顺后仍缺必填项的才不执行，并把收到的键与原文回给模型。模型输出被最大长度截断时，参数 JSON 会被尽量补齐——只读工具（读、列、搜、检索）照用，有副作用的（`run_command` / `write_file` / `edit_file` / `remember` / `forget` / `delegate`）一律拒绝并告诉模型原因，不会把截掉了 `content` 的 `write_file` 当成空文件写下去。同一轮里相同参数的只读调用复用已有结果，但只缓存成功的，临时的超时与报错不会被复用。

这不是沙箱：指令在你的机器上、以你的权限执行，安全边界在于「每条指令都可见、默认需经确认」。请勿将工作目录指向不希望被改动的位置。

## 录 · 记忆

- 模型在对谈中自行记下长期有效的事（偏好、身份、项目约定、日后会再用到的结论），一条一句，跨对话可翻；设置页「记忆」一栏可改、可删、可手记，也可整体关闭
- 记忆的内容不随每次请求发送：系统提示只告知模型有这份记忆、何时该记、何时该看，条目要靠 `recall` 才看得到，旧对话要靠 `search_conversations` 找到、`read_conversation` 才读得到——新话题不会被过往扰乱
- 收敛：`remember` 带 `replaces` 可把相近条目合并成一条，`forget` 删去过时的；上限 200 条，满了模型会被告知先清理
- 五件工具都在浏览器里完成，不经桥接、不需确认，每一步都在「行迹」里可见；翻过的记忆、查到与读过的旧谈会列在回复底部的「出处」里，点开各归其处；条目随备份导出、导入时按 id 与原文去重

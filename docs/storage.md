# 存储与备份

[← 文档目录](README.md) · [English](en/storage.md)

对话、卷宗、附件与配置都落在一个存储目录里（默认 `~/.yan/`）：`对话/` 一段对话一个 JSON 文件、复制即备份，`卷宗/` 是成品与收进来的文件，`附件/` 是对话里附件的原件（一件一个原件加一份同名 `.json` 元数据），`技能/` 是言自己认的技能（见[技能](skills.md)），`游目/` 是游目自己的浏览器（依赖、登录与收藏、下载、自带内核，见[游目](stage.md)），`环境/` 是给模型备的 Python 与工具链（见[沙箱环境](env.md)），`配置.json` 是设置、模型配置（含 API Key）、记忆与草稿——几个浏览器共用这一份，不再各存一套（两处同开、各改各的也不互相盖：写之前先比磁盘上的那份，别处改过就按上次对齐的那份三方合并——自己改的取自己的、没改的取对方的；在别处删了的对话，这边也跟着删，不会推回去复活）；浏览器里那份只是缓存，以及桥接中途断开时的暂存，接上后与存储目录对齐。设置 → 通用里只有一个「存储位置」，换到别处时整份拷过去（那里已有言的数据就直接用；`环境/` 不拷，到新处重新准备），旧处原样留着；有对话正在作答（哪个页面的都算，后台的帮手也算）时不换，等答完再换——拷到一半那边还往旧处写，搬过去的就缺了那一截。附件原件落盘不成时暂存浏览器的 IndexedDB，接上后推进 `附件/`。右栏开了哪几段、每段多宽记在本机的 `localStorage`（`yan-split-v2`），不随存储目录走，也不进备份。不经任何云端

## 备份

- 备份导出与导入：导出时可勾选「含附件原件」；导入采用合并策略（按 id 跳过已存在的对话 / 模型 / 卷宗，并合并未冲突的草稿）；备份不含 API Key

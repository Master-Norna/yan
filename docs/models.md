## 接入模型

接 Anthropic 时页面与桥接内部仍是 OpenAI 的格式，只在最外面换一层：请求换成 Messages API 的（system 单列、工具结果并进 user、工具定义换成 input_schema、思考档位老模型换算成思考预算、4.6 起换成 adaptive 与 effort，开了思考时不传 temperature），事件流换回 OpenAI 风格的分块（思考块带签名回传给下一轮，带工具调用的那一轮 Anthropic 要求如此；新一代的签名记着它之前的整段前文，一答之内改了较早的往来——旧截图换成一行字、撮要压掉前几轮——改处之后的思考块就不再送回，免得被拒）；图片与 PDF 原件照送，别的文件只留一行说明。

接 ChatGPT 订阅（接口选「ChatGPT 订阅」）走 OpenAI 给开源与本机应用开的「Sign in with ChatGPT」：卡片上点「登录」，桥接在 `127.0.0.1` 上临时开一个回调口、用系统浏览器打开 OpenAI 的授权页，用 ChatGPT 账号同意后回到言即可（头一回登记时 OpenAI 发下这台机器自己的 client_id，往后登录沿用它；在 ChatGPT 设置里能看到言、查用量、给它设每周上限）。凭证只在桥接里，存在存储根下的 `ChatGPT 登录.json`，不进页面、不进备份；访问令牌一小时，快过期时桥接用刷新令牌换新，换新被拒（登录已失效）才清掉、请你重新登录；「退出登录」向 OpenAI 吊销刷新令牌。请求直发公开的 Responses API（`api.openai.com/v1/responses`），带言自己的提示与工具，不经 Codex 那一层；桥接把请求换成 Responses 的、事件流换回 OpenAI 风格的分块。不填 Base URL 与 API Key，模型列表取这个账号可用的那几个，各模型认的思考档位随列表一起来（探档位不必真发请求）。带工具调用的那一轮，思考的加密原件随下一轮送回；同一段对话带固定的缓存键，前文走缓存。不收 temperature、输出上限，用量计入订阅额度；额度用完、套餐不支持这类拒绝换成中文说明。旧版的「Codex 订阅」（借 Codex CLI 的登录）已撤下，存着的这类模型自动改成 ChatGPT 订阅，点一回登录即可。

接硅基流动（接口第一项「硅基流动」，图文步骤见[在言中使用硅基流动](siliconflow.md)）即 OpenAI 兼容接口，单列一档只为填好地址（`https://api.siliconflow.cn/v1`，国际站可改成 `.com`）；换走时地址一并清掉。获取列表只取对话模型（带 `sub_type=chat`，画图、向量、语音模型不列）。思考档位：DeepSeek-V4、GLM-5.2 认 `reasoning_effort`，只有 high、max 两档；别的模型（Qwen3 之类）换成 `enable_thinking` 与 `thinking_budget`（上限 32768）。先前选「OpenAI 兼容」、地址填硅基流动的，桥接按地址一样认得。

- temperature 留空即不传、由接口定（有的接口只认默认值，传了反倒报错），填了才传；`max_tokens` 只有接 Anthropic 时才有（Messages API 必填，默认 32000），OpenAI 兼容接口不传这个字段、由服务端按模型上限定，不会因为手写了个小数而把长回答截断。用量上限可选，支持 `k`（千）、`m`（百万）、`e`（亿）：留空不限，右上角改报已耗；设了则「余墨」随用量递减，耗尽后该对话暂停，更换模型或调高上限即可在原处续写。用量在每一答收尾时结算，停止、断网、工具链中途出错也照记（接口没给 usage 的那一轮按估算）；一答开工时先按「提示 + 最大输出」预留额度，几段对话同时开工时后来的看得见先来的已占多少，不会都以为还剩一样多而合计超卖。
- 点右上角那一笔墨进模型一栏，顶上是用量卡：一年一卷，一日一点墨，五档浓淡（点也随之大小）按这一年有用量的日子分；今天圈朱，指上一点浮出那天主答、帮手、旁注、审查、生图各多少（拟题、整理前文算进主答，生图记张数）；下面一排既是这一年各类的合计，也是开关——点一类只看那一类。有往年的记录才列出年份可翻。数记在存储根下的 `用量.json`，页面每花一笔按本地日期、按类报给桥接，由桥接往上加（几页同开也不必合并）；余墨照旧记在模型上，两者互不相干。旧版没有这本账，从升级那天记起
- 模型选择在发送键旁，菜单底部是思考强度（默认 / 低 / 中 / 高 / 最高；没有「关」——要它少想就选「低」）：每个模型分别记住所选档位，切换模型时恢复该模型的选择，新对话也沿用；OpenAI 系接口发送 `reasoning_effort`，DashScope 兼容模式与硅基流动的 Qwen 之类发送 `enable_thinking` 与 `thinking_budget`，「默认」不带字段。各家认的档位不一样（有的只有 low / medium / xhigh，有的多 minimal 或 max，有的压根不认这个字段）：选定一个模型时（菜单里选、设置里选或填模型 ID、获取列表、测试连接）会自动探一下——故意送一个不存在的档位，接口按 OpenAI 的样子报错就把报错里列的几档记到模型上，说不认识 `reasoning_effort` 就记成不认（菜单上只剩「默认」、不带字段），照单全收的中转站按通用四档列；一个模型只探一次，换了模型再探，鉴权与网络之类的错不算探过。探到的填在模型高级配置的「思考档位」里，可以手改（手改的就是定论，测试连接也不重探；换了模型才作废）；探的是这个模型此刻的身份，此前记的档位一律不沿用；菜单只列这个模型认的几档，选了它不认的档位就落到最接近的一档（选「最高」而它只到 high 就用 high），发送键旁的标签写实际送出的那一档。没探过、又撞上接口拒绝的，仍从报错里记下并换最接近的一档重发
- 工具参数按 JSON 收，模型写得潦草也尽量救回来：裹了代码围栏、结尾多一个逗号、整段被 max_tokens 截断、把参数对象又编码成字符串，都会先修再解析；实在解析不了才算失败，回给模型的话里带上具体的出错位置、这件工具该收的参数与收到的原文，让它一次就能改对
- 工具调用（function calling，可在模型高级配置中关闭）：`search_web` 免 Key 检索（桥接直接请求必应，同时至多三个、前后错开；必应时而把直接请求认作脚本、只认第一个词，结果里后面的词都对不上时，换无头浏览器再搜一回，DuckDuckGo 垫底；各家都对不上的照给并标明「未必可信」）、`fetch_page` 读取网页与 PDF 正文（一段 2.4 万字，长文按 `offset` 续读；PDF 在页面这头抽字，与附件同一套；网页拒了直接请求、或要跑脚本才出内容的，交给无头浏览器开一页再取）、`http_request` 向公网接口发请求（GET / POST / PUT / PATCH / DELETE / HEAD，带请求头与请求体，回状态码、响应头与正文，文本截到 6 万字、二进制只报类型与大小；本机 127.0.0.1 / localhost 放行——模型自己开的本机服务本就该能测，局域网等内网地址照旧拒，且和执事接口一样只受理本站页面的请求；旁注只许 GET、HEAD）、`read_document` 按页码或关键词翻阅对话附件与卷宗中的文档、`run_js` 在隔离沙箱里算一段 JavaScript（算术统计、日期、正则、JSON 变换——心算易错的交给它；沙箱是 `preview.html` 那个 origin 为 null、CSP 不许联网的 iframe 里的一个 Worker，fetch / importScripts / indexedDB 都抹掉，只剩标准 JS；单个表达式直接算值，语句块用 `return` 交回，`console.log` 一并带回；超时把 Worker 整个杀掉；不经桥接）、`download_file` 把网上的文件存进工作目录或卷宗（本机放行、内网拒，同上；最大 64 MB，省略路径按网址里的文件名，同名加 (2)，计入这一答的改动摘要），行里另有 `update_plan`（任务不止几步时列一份计划给用户看，行迹里画成一张清单卡：○ 待做、▶ 正在做、✓ 做完、– 不做了，每次给完整清单，下一问的行迹摘要里带着它）与 `update_intent`（意：跨多答的长活立一份结论图，存于目录 `.yan/意.json`、换对话也沿用，见[言与行 · 执事](work.md#意)）；全部合并在「行迹」折叠区，每一步以转圈 / ✓ / × 表示运行、成功与失败；同一轮的重复调用直接复用已有结果（只复用成功的）；同一轮里相邻的只读调用（读文件、搜索、翻网页、翻记忆）并行执行，结果仍按原顺序回传；执行、写入、修改与请示逐个来
- 联网回答结束后从成功的搜索与网页读取步骤生成去重的「出处」卡片，已阅读全文的来源单独标记
- `ask_user`：下一步取决于用户的选择时，模型可弹出一张小表单（最多 8 题、通常 1–3 题，一题一页可前后翻，每题 2–4 个选项，可多选、可自行填写；单选题里选项与自行填写二选一）从输入框上方浮出；对谈与执事都可用，答案随「行迹」摘要带进后续轮次
- 内置提示词（通用系统提示、执事工作法、旁注聚焦句、各工具的说明）全部在 [`prompts/`](../prompts/README.md) 目录，改完刷新页面即生效；`support.js` 只做拼接

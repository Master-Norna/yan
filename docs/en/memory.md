# Memory

[← Docs](README.md) · [中文](../memory.md)

- Memory is what the model knows about you (preferences, identity, agreements, ongoing work), kept as one text per category and carried across chats. It's switched on under **Duties** in settings: give **Memory optimization** an API and a model, and only then is it included and recorded. Turned off, nothing is included or recorded, and the memory stays
- Bringing it into chats: the whole memory goes into the system prompt, one paragraph per category, so the model doesn't have to look anything up. It's frozen at each chat's first message; later saves and optimization don't change it, so the system prompt stays the same and the cache keeps working. There's no length cap
- Remembering: the main model uses `remember` to write a category's full revised text — keeping what still holds, merging in what's new, dropping what's outdated or what you asked it to forget; writing it empty deletes the category. It shows as “Remember” under Steps. One text per category rather than one item per fact: with separate items the model tends to add a new one instead of revising the old, and memory gets fragmented; with one text per category, remembering means rewriting the whole category, so old notes merge in naturally. Only the main model gets this; side notes only see the memory, and subagents don't carry it
- Optimization: after the memory changes (saved by the model, or edited by you in settings), the Memory optimization duty goes over it when an answer settles — merging repeats, fixing contradictions, cutting passing details and filler — and answers with the full text of only the categories it changes; the rest stay word for word. It reads only the memory, not your chats, so it only spends tokens when the memory has actually changed; a category edited after it was sent isn't overwritten. A short notice says how many categories it touched, and the tokens are counted under **Memory** on the usage card
- Past chats: `search_conversations` searches by keyword (with no keyword it lists the most recent), and `read_conversation` reads a chat's main thread in parts. These two are always available, whether memory is on or not. Chats read are listed under **Sources** at the bottom of the reply, each opening that chat
- The **Memory** tab in settings lists the categories on the left and the selected one's full text on the right; click the text to edit it, and emptying it deletes the category. Category names can be edited in place, and renaming one to an existing name merges them. Memory is included in backup export; on import, a category's text is appended to the one with the same name, skipping lines already there. Old one-item-per-fact memory is merged into one text per category when loaded

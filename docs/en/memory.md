# Memory

[← Docs](README.md) · [中文](../memory.md)

- Memory keeps useful cross-chat context about you: background, preferences, agreements, plans, and experiences. It is stored locally as one text per category. The main model decides what to remember, update, or forget; no separate model is needed. The **Include in chats** switch under Settings → Memory controls reading and writing. Turning it off keeps saved content
- There are two layers: cross-chat memory is saved with settings; practices and experience specific to a working folder go in that folder's `.yan/记忆.md`, attached to each question there independently of this switch (see [Chat and Agent · Memory](work.md#memory))
- Each question includes the latest full memory in the system prompt, one section per category. Tool rounds within that answer keep the same prompt. Changes from other chats or settings appear on the next question. Unchanged content keeps the prompt stable; updates affect prompt caching from the changed position onward. There is no storage length cap
- The main model calls `remember` with a category's full revised text, keeping what still holds, incorporating new information, and removing outdated or unwanted content. Empty text deletes the category. Keep the current account of each fact; date significant changes when useful. Categories may have paragraphs and lists, without repeating the full background on each update. Only the main model can write; side notes can read global memory, and subagents do not receive it
- Writes check the version read for this answer. If another chat or settings changed that category, the overwrite is rejected and its latest text is returned for the model to revise. Successful writes also return the saved text for subsequent tool rounds. There is no background optimization or separate memory-model request
- `search_conversations` searches past chats by keyword, or lists recent chats when no keyword is supplied. `read_conversation` reads a chat's main thread in parts. Both remain available with memory off. Read chats appear under **Sources**, linking back to the conversation
- Settings lists categories on the left and the selected text on the right. Choose **Modify** to edit; empty text deletes a category. Renaming to an existing category merges them. Backups include memory; imports merge same-name text while skipping existing lines. Older one-fact entries are merged by category on load. The former Memory optimization switch moves here; its API and model configuration are removed while saved memories are preserved

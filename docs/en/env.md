# Sandbox environment

[← Docs](README.md) · [中文](../env.md)

In **Settings → Environment**, prepare a self-contained development environment for the model: a standalone Python 3.12 (managed by uv) and common tools, installed in `环境/` under the storage location, neither depending on nor changing the system's Python and PATH. Processes started by the bridge — the model's commands, MCP servers — all use it: `python`, `pip`, `uv` and `uvx` point into the environment, `npm i -g` installs into it, and the model can install whatever library it's missing.

The tool packs are Windows-only: on macOS, **Settings → Environment** says so and disables setup — use the system Python and Node (e.g. via Homebrew); processes started by the bridge don't use this environment.

- One card per tool group, name on the left and status on the right: an empty box is not selected, solid vermilion is selected and waiting to install, a check mark is installed; installed but unticked is marked **To remove**. **Set up environment** brings the environment in line with the ticks — ticked groups are installed, unticked ones removed (packages still used by another group or by **Extra packages** stay). Options: data processing (numpy, pandas, matplotlib…), office documents (reading and writing Word, PowerPoint, Excel, PDF; pandoc), web scraping, images (Pillow, OpenCV), audio and video (ffmpeg; the bridge also uses it to preview videos: a file with an mp4 extension but a container the browser can't read, such as MPEG-TS, is remuxed into an MP4 shell without re-encoding before playing; the latest three remuxed files are kept in `环境/cache/视频/`, see `server/video.js`), front-end tools (TypeScript, tsx, Prettier), and several compiler toolchains: C / C++ (zig's bundled clang, with `cc`, `gcc`, `c++` and `g++` all pointing to it, plus cmake and ninja, no Visual Studio needed), Go, Rust (rustup-managed GNU toolchain, also without Visual Studio), Java (Temurin JDK 21). Package names outside the list can be added. The list is in `server/env/packs.js`; to add a group, follow the existing entries: packages on PyPI / npm need only the name; others need a `fetch` step to download and unpack, plus the folders, PATH and environment variables (such as `GOROOT`, `CARGO_HOME`, `JAVA_HOME`).
- Download sources: mirrors in mainland China use Tsinghua (PyPI), USTC (Python itself), npmmirror, Nanjing University (Go, Rust, JDK), goproxy.cn and rsproxy (crates); the official sources each use their own. You don't choose: during setup, Yan fetches the first 2 MB of the same common package from each side, compares speeds and picks the faster (with a proxy on, the domestic mirrors are routed out too and become slower; see `server/mirror.js`), recording it in `已备.json`. Packages the model installs later on its own (pip, npm, go get, cargo) use the same route. The Python-only groups take a minute or two; compiler toolchains are large (C / C++ about 500 MB, Go about 250 MB, Rust about 850 MB, Java about 330 MB), as shown on the cards.
- When uv installs Python, it doesn't put entry points in `~\.local\bin` or register anything in the registry; all entry points are in `环境/bin`.
- Executables shipped inside packages under irregular names (such as the ffmpeg in imageio-ffmpeg) get an entry point of the plain name in `环境/bin`.
- The environment isn't copied when the storage location moves (virtual environments record absolute paths); just set it up again in the new place. **Clear** deletes it entirely.

# Skills

[← Docs](README.md) · [中文](../skills.md)

A skill is a way of doing something that's read only when needed: a name, when to use it, and instructions. It's stored as a folder containing a `SKILL.md`, whose YAML header gives `name` and `description` (what it does, when to use it) and whose body says how; the same folder can hold reference documents, templates and scripts. Yan uses Claude Code's folder and `SKILL.md` format but reads only the fields and features described here.

- **Where they go**: Yan recognizes only one place, `技能/` under the storage root (by default `~/.yan/技能/`; **Settings → Skills** shows the actual location). Recognized skills are available to the model by default and can be set to manual selection only. A skill folder may sit up to three levels below `技能/` (such as `技能/some-group/some-skill/SKILL.md`); folders starting with a dot are ignored, and when names match (ignoring case), the first in folder order wins.
- **Bundled with Yan**: Yan comes with six — code review (code-review), deep research (deep-research), design (design), learning (learn), skill creation (skill-creator), and caelison for composing with Tianlai (requires Tianlai; invoked only by name, not listed for the model). Three carry optional small tools: skill-creator's `scripts/check-skill.mjs` (checks a skill's header, references and possible secrets) and `references/frontmatter.md`, deep-research's `scripts/check-links.mjs` (checks the links in a report), and design's `assets/prototype.html` (a starter page for prototypes). The scripts are written for Node with no dependencies. They're copied into the skills folder the first time skills are listed, after which you can edit and delete them like your own. Deleted ones aren't copied back, existing ones of the same name aren't overwritten, and new ones added in a later version are copied (what's been given is recorded in `.言自带` in the skills folder).
- **Skills from elsewhere**: `~/.claude/skills`, a project's `.claude/skills`, or ones from the web — copy the whole folder in to use it. Or ask the model to fetch it: in Agent mode the system prompt says where the skills folder is, so "copy such-and-such skill over" is enough.
- **Writing one**: in **Settings → Skills**, click **＋** and write the name, **When to use** and **Instructions** in place; it's saved as `技能/<name>/SKILL.md` when focus leaves the editor or you click **Done**. Click a row to expand it; the **Edit** below turns it into input fields (renaming renames the folder, and other header fields are kept as is). **Delete** at the end of the row deletes it along with the scripts and references in its folder (after asking). **Open** opens the skills folder in the file manager.
- **Bundled files**: a small sheet at the end of the row shows how many files come with it (scripts and references aren't told apart). Expanded, the instructions are followed by "Bundled: n files", grouped by folder — with no more than 12 files, all folders are open; with more, they start collapsed. Each folder lists at most 12 files; click the rest to open that folder in the file manager. Click a file to view it in the previewer (the same one as Files, for text, code, images, PDFs and web pages), rather than expanding it in the settings page.
- **How the model uses them**: there's no separate tool. Each skill's name and `description` are listed in the system prompt; when the model works on something related, it first reads `SKILL.md` by skill name with `read_document`, then reads references in the same folder as "skill-name/path" as instructed. The `SKILL.md` it reads states the skill folder at the top, so in Agent mode it runs the skill's own scripts from there. The model can read text files; without a page number or keyword, it gets up to the first 60,000 characters. Chat, Agent, side threads and subagents can all read them.
- **Invoking by name**: in the input box, **＋ → Skills**, pick one (search at the top matches both name and when-to-use), and its instructions are attached to the question as an attachment, so the model needn't look it up.
- **Two Claude Code header fields**: `disable-model-invocation: true` keeps it out of the model's system prompt and the list returned by `read_document` (in settings, click that skill's pouch icon to toggle; a faded pouch means name-only). `user-invocable: false` keeps it out of the **＋** picker.
- **Steps**: the step that reads a skill is labeled as a skill, titled with the skill's name for the main instructions and the full name for bundled files.
- **When changes take effect**: the folder is rescanned before each main answer with tools enabled, so added, edited or deleted skills are recognized from the next question. The catalogue includes just names and `description` fields in the system prompt; instructions are fetched when used, so many skills add only a few lines.
- **Presets**: a preset without the **Documents** tool group gives the model neither the skills catalogue nor the reading tool. You can still attach a skill to a question from **＋**.

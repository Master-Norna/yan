# Skill

[← 文档目录](README.md) · [English](en/skills.md)

一份 Skill 是一段用到才看的做法：名字、何时用、正文。它存作一个目录，里面有一个 `SKILL.md`，头上用 YAML 写 `name` 与 `description`（做什么、何时用），正文写怎么做，同目录可另附参考文档、模板与脚本。写法与 Claude Code 的 skills 相同，现成的 Skill 拷进来即可用。

- **放在哪**：言只认存储根的 `技能/` 一处（默认 `~/.yan/技能/`，设置 → Skill 里写着实际位置），放进来的都给模型，不设开合。Skill 目录可以隔着一两层（如 `技能/某组/某技能/SKILL.md`），点开头的目录不认；同名的按目录次序先到的为准。
- **随言带来的**：言自带六份——代码审阅（code-review）、深度研究（deep-research）、设计（design）、学习（learn）、Skill 创建（skill-creator），以及与天籁作曲的 caelison（须接天籁，只凭点名、不进模型的目录）。其中三份带着可选的小工具：skill-creator 的 `scripts/check-skill.mjs`（查一份 Skill 的头部、引用与疑似密钥）与 `references/frontmatter.md`，deep-research 的 `scripts/check-links.mjs`（查报告里的链接），design 的 `assets/prototype.html`（原型起手页）；脚本用 Node 写、不装依赖。头一回列 Skill 时拷进 Skill 目录，此后与自己写的一样可改可删；删了的不再拷回，同名的已在不覆盖，下一版新添的照拷（给过哪些记在 Skill 目录的 `.言自带`）。
- **别处的 Skill**：`~/.claude/skills`、项目里的 `.claude/skills`、网上的，要用就把整个文件夹拷进来。也可叫模型去找——有执事时系统提示里写着 Skill 目录在哪，说一声「把某某 Skill 拷过来」即可。
- **写一份**：设置 → Skill，点「＋」就地写名字、何时用与正文，焦点离开即存成 `技能/<名字>/SKILL.md`；点一行摊开看，底下「改」才成输入框（改名时目录跟着改，头上别的几项原样留着），行末的「删」连同目录里的脚本与参考一并删掉（先问一声）。「打开」在文件管理器里打开 Skill 目录。
- **附带的件**：行尾一枚小纸写着附带几件（不分脚本、参考）。摊开后正文下列「附带 n 件」，按夹归拢——附件不过 12 件夹全开着，多了先收起；一夹至多列 12 件，余下的点了在文件管理器里打开那一夹。点一件进预览器看（与卷宗同一个，文本、代码、图、PDF、网页都看得），不在设置页里摊开。
- **模型怎么用**：不另设工具。各 Skill 的名字与 `description` 列在系统提示里，模型做到相关的事先用「翻阅文档」（`read_document`）凭 Skill 名翻 `SKILL.md`，再按说明以「Skill 名/路径」翻同目录的参考；翻到的 `SKILL.md` 开头注明 Skill 目录，在行里要跑 Skill 自带的脚本就照这个目录。Skill 的文件整份给（至多六万字），不像长文档那样只给开头。言、行、旁注与帮手都翻得到。
- **人点名用**：输入框「＋」→「Skill」，挑一份（顶上可查，名字与何时用都认），那份说明即作一件附件置于案上、随这一问附上，模型不必再去翻。
- **Claude Code 头上的两项**：`disable-model-invocation: true` 只凭人点名、不列进系统提示，翻阅文档的清单里也不露（设置里点那一份的锦囊即切换，淡下去的锦囊就是只凭点名）；`user-invocable: false` 不列进「＋」，只给模型。
- **行迹**：翻 Skill 的那一步标作「Skill」，题写 Skill 名。
- **何时生效**：每一答开工前重扫一遍，放进去、改过、删掉的下一问就认。只有 `description` 进系统提示，正文用到才取，Skill 多了也只多几行。
- **预设**：没挑「翻文档」这一组的预设，连同 Skill 一并不给。

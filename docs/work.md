# 言与行 · 执事

[← 文档目录](README.md)

## 目录决定

言与行不是两个入口，而是一段对话有没有绑工作目录。欢迎页输入框上方的「目录」小签空着，这一纸就是**言 · 对谈**；填了路径（或点「选择…」以系统对话框选取，Windows 上是资源管理器风格的现代对话框，带地址栏与搜索；不记「最近选过的目录」，每次自己选——删掉的目录若还列着，点一下又会把它绑回来、发消息时重建），就是**行 · 执事**。侧栏的一枚印只显示当前的态，改态去目录签。目录可以在对话中途绑上——标题下的「绑定目录」——此后工具与提示词随之而变，历史一字不丢，适合先聊清一个想法、再带着上下文动手；点目录路径可更换或解开，解开即回到言。侧栏历史是一条时间线（置顶 / 今天 / 过去七天 / 更早）：绑了同一目录的对话归在一个带「工」印的组里，组按组内最近动过的那条排（一条有动静，整组靠前），组内按时间；没绑目录的对话按自己的时间散在其间；点组头收起 / 展开（收起时仍露出当前打开的那条），组头右侧的「＋」在该目录另起一纸。

## 文件工具

言与行的文件工具落脚处、作风与确认各不相同：行拿六件（含逐字替换与代码检索），言拿产出文件所需的四件（run_command / write_file / read_file / list_files）并用短说明；要它看看电脑就用 `run_command` 直查，沙箱的目录约束只管改动、不管查看。行落在工作目录，系统提示是执事的工作法（先定位再阅读、先说方案、最小改动、改后验证）；言落在卷宗目录，除明确要求检查电脑外，只在用户要可交付文件时动用文件工具。执事是一个只做代码工作的轻量 Agent，六件文件工具：

- `list_files`：列出目录树（目录以 `/` 结尾，文件后跟字节数）；给 `pattern` 时按 glob 找文件（`*.ts`、`src/**/*.js`），跳过 node_modules、.git 等
- `search_files`：按正则（或原文）在文本文件里逐行检索，返回 `文件:行号:内容`，可限定子目录（给一件文件就只搜它）与 glob；用于定位代码。写不成的正则按字面搜，结果前头说一声。正则在某个文件上回溯超过两秒即中止并告诉模型改写，写坏的正则卡不死桥接
- `read_file`：读取文本文件，带行号、可按 offset / limit 分段；认得 UTF-8（含 BOM）、UTF-16（Windows PowerShell 5.1 的 `>` 与 `Out-File` 写出的就是它）与 GBK，编码不是 UTF-8 的会告诉模型
- `edit_file`：精确替换一段文本，`old` 必须与文件逐字一致且唯一（或显式 `replace_all`），CRLF 文件自动保持换行，UTF-16 与带 BOM 的文件照原来的编码写回（GBK 的不逐字改，请模型整体重写或先转码）；**本段对话里没读过或写过的文件不允许编辑**，模型必须对着真实内容改；`old` 对不上时，报错附上文件里最像的那一段（照现在的样子、带行号），模型照着重改，不必先重读；步骤卡上以前后片段展示改动
- `write_file`：新建或整体重写文件
- `run_command`：在工作目录中执行一条指令（Windows 上有 PowerShell 7 就用它，没装的退回系统自带的 5.1；其他系统使用 sh。输入输出均为 UTF-8，指令另行解析、不受命令行引号规则影响，写错了报的是读得懂的解析错；输出里的终端颜色码去掉），返回退出码与输出；默认 120 秒超时，不设上限；cmdlet 出错同样以非零退出码返回，错误文本已还原为纯文字。开发服务器、长任务这类要跑一阵的，带 `background` 放到后台：先回几秒的输出与一个编号（bg1…）；**它结束时会叫醒模型**（见下文「后台指令结束即叫醒」），不必轮询；要看中途输出或提前结束它，用 `check_command`；桥接退出时后台指令一并收掉

路径相对工作目录；设置 → 工具 →「文件工具可及范围」默认「全盘」（问而后行开着沙箱时不生效，一律目录内），此时完整的绝对路径可以指向目录之外（系统级配置、别处的资料都读得到，写之前模型会先说明），改成「目录内」则一律拒绝越出（含借符号链接 / junction 越出的情形；列目录与检索不跟进链接，链接以 `@` 标出）；工作目录须是完整限定的绝对路径（Windows 上须带盘符）；执事接口只接受本站页面与 VS Code Webview 的请求，`file://` 页面接不上桥接；文件系统错误以可读说明返回。系统提示只交代环境（目录、平台、shell、沙箱的界）与收尾时交代几句；怎么读、怎么改、什么不能猜，写在各工具的说明里（见 `prompts/`）。

## 后台指令结束即叫醒

后台指令挂上就不必守着：桥接那头等它结束再回话，结果（退出码、用时、之后的新输出）照帮手回报的路子寄给这段对话。模型布置完、只剩等它，这一答就写完；它结束时另起一答，两答之间一道细线「后台 bg1 已结束」（退出码不为 0 的写出退出码），点它回到挂它的那一步。模型布置完还在干别的，结果就在回合边界递进这一答，行迹里它到达的那一刻落一小步「回报 · 后台 bg1 已结束」，与补言一样大小，不另起一答。挂它的那一步上随之写「已结束 · 退出码 n」。

所以「过一阵再做」不需要别的机制：挂一条先等待的后台指令（`Start-Sleep -Seconds 3600; …`）就是定时，写一个条件满足才退出的小循环就是盯着某件事，醒来再挂下一条就是周期。页面刷新后照样等上；几处页面同开，桥接只报一回；模型自己用 `check_command` 看到它结束的，不再叫醒。代价是本机的：桥接退出（重启 start.cmd、关机）后台指令随之结束，签上写「随桥接重启而止」；电脑睡眠时等待的计时也停着。帮手挂的后台指令叫醒的是帮手自己（见下文「差遣」）。

## 账本

跨多答的长活，任务活在目录里、不活在哪一段对话里：模型在目录下立一份 `.yan/账本.md`，自己维护，只记对这件工程持续有约束的——目标与达标标准、定下的约束与取舍、计划与进展、走不通的路；过时的删、相近的并，不记流水账。每一答开工时读一回，冠在这一问的开头送给模型（之前的问不带，免得一份账本背上几十遍；附在问上不进系统提示，改了也不冲掉前面的缓存）。于是压缩了前文、被回报或后台指令叫醒另起一答、换一段对话绑同一目录接着做，看到的都是同一份。附着全文即算读过，主模型可径直 `edit_file`。过了 3000 字，冠上去时提一句请它取舍。帮手领命时附一份只读的（账本只由主对话写），领命那一刻现读——先立下约束再派活，帮手拿到的就是刚立的那份；开头提过的一条小约束不会在分出去的活里丢了。没有这个文件就什么都不附。

## 行迹

上一答的行迹会压成一行「［上一答的行迹］…」冠在下一问的开头送给模型（页面上不显示），它才记得自己读过、改过哪些文件，不必每轮从头再探。摘要不接在助手自己的话后面：那样模型会把它学成自己回复的格式，答末照写一行。

执事对话里的「行迹」是一条时间线：模型边做边说的话与各步按先后穿插排列，进行中摊开可看过程，题头写「工作中 · n 秒」边做边走，做完自动收起成一行「工作了 n 秒 · n 步 · 改 n 个文件」，只留最后的总结在外，点开可回看全过程；各步默认摊开的只有两种：目录清单（露前 10 行）与修改的 diff（两侧各 10 行），底下一行「展开全部」可看全；指令输出、读取、搜索、检索与翻阅这些有明确行数、往往又长的，默认折起（一答几十次检索，命中全摊开要占一整屏），标题行上有结果与行数，点标题行展开；报错的也折起。运行中摊开、运行完收起是行迹与帮手时间线的定例：整答收尾时行迹一律收起，帮手做完它的小时间线也一并收起。对谈里仍是折起的注脚。每一答的末尾附一行改动摘要「n 个文件已更改 · +增 −减」，点开可见逐文件的行数增减（`edit_file` 按行级 diff 计，`write_file` 新建按全文计、覆盖按新旧行数计），逐轮可查。思绪与各步都有进行中的呼吸点、完成后的勾；后几轮的思绪各在自己的分组里，工具参数还在流式拟定时先显示「正在拟 写入 xxx · n 字」。

## 差遣（子 Agent）

遇到可以自成一段的大块子任务（通读一批文件并归纳、在某个模块里排查一个问题、按已定方案实现独立的一部分），模型可用 `delegate` 差遣一名「帮手」去做。帮手用同一个模型、同一个工作目录、同一套工具（但不再差遣、不请示用户，记忆只读——可 `recall`、查旧谈，不能 `remember` / `forget`）另起一段对话独立跑自己的工具轮次（默认最多 40 轮，设置里可改），做完把最后一轮的回报连同改动摘要寄回主模型；帮手看不到主对话，任务说明得把背景、目标、边界与要回报的内容写全。帮手的思考强度由主模型按活的难易给（`effort`：照章办事用 low，要权衡的 medium / high，难查的毛病、设计与复查用 max；模型不认的那一档落到最近的一档），省略则同主答所选，续派沿用它上一趟的；所用档位标在签的计数之后（「… · 思考低」）。同一轮里可差遣多名帮手，他们并行开工（分派时由主模型保证各自改的文件不重叠；桥接那头同一文件的写入与修改按先后排队，`edit_file` 的读—改—写在锁内完成，不同文件照常并行；`run_command` 不拿锁——对谈的工作目录都是卷宗，整目录的锁会让所有对话的指令排成一队，指令恰好改到 `edit_file` 手里的文件时由原文比对兜住）。页面上每名帮手是行迹里一枚带「遣」印、衬淡金的「差遣」签（朱色留给印章与删减），只写标题与「n 步 · 改 m 个文件 · 几秒」（做着时是「n 步 · 几秒」，用时边做边走），做事时呼吸；点开是一扇全屏的窗，里面是帮手自己的小时间线——每轮的思绪、说的话、各步，与主行迹同一套画法：进行中摊开、最新的思绪与话实时跟着流，每一轮的各步折成一行「检索 18 · 翻阅网页 30 · 48 步」，那一轮跑着时摊开、跑完收起（亲手开合过的不动），说的话与末尾的回报始终在外，不被几十条检索顶到几屏之下；帮手工作期间输入框上方常驻一条帮手条（一行一名，写着它正在做的那一步，点一下开它的窗），行迹标题也显示「帮手「…」· n 步 · 进行中」——派它的那一答写完了也一样；指令沿用所在对话的权限档位，改动计入这一答的改动摘要与「改 n 个文件」，用量计入上下文成本，下一问的行迹摘要里也带着它改过的文件。帮手读过的文件不算主模型读过（反之亦然）：谁要改，谁先读。对谈模式同样可以差遣（帮手带联网与文档工具）。

帮手在后台做，不随派它的那一答收尾：主模型派完活、自己也没别的可做，这一答就写完了，没有谁醒着干等。帮手做完，回报若赶上这段对话正在作答（主模型还在忙别的，或用户刚问了一句），就进那一答的收件口，在回合边界递上，行迹里它到达的那一刻落一小步「回报 · 帮手「…」回报」（点开即它的窗）；没在作答，就另起一答，回报作这一问——页面上不是用户的气泡，而是一道细线，中间写「帮手「…」回报」（未做完的写「未完成」），点名字开它的窗；同一刻到的几份并成一问。这样一件长活分几段落在几答里，每一段写了什么都留在正文里看得到，不会被下一轮的话冲掉。另起的那一问前面照例冠着上一答的行迹，还没回来的帮手在里头记作「后台进行中」。这期间输入框照常可用：写了话是新的一问；案上空着时印是「止」，按下即叫停后台所有帮手（叫停的不回报，也就不再另起一答）。帮手的用量记在派它的那一答上，做完时补记。页面刷新或关掉，后台的帮手随之中断，签上写明。派它的那一答若断着（断网中断、报错），回报不另起一答——另起的多半也是断，还会在断处底下留一截，续上那一答时成了残留、主线也分成两头：回报先记在这段对话上，中断的那一答随即自己续上、回报在开工时递进去；还断着就原样记着，等下一答（手点「继续生成」、重试或新的一问）开工时递上。旧对话里已留下的那截「回报 + 没写出东西的空答」，续写时收回来一并递上。

帮手与主答守同一句话：**只剩等待就睡，信到了就醒**。帮手挂了后台指令（训练、长构建、等一个条件），说完这一趟手上只剩它在跑，就把此刻的话作为进展交给主对话（「帮手「…」暂告一段，正等后台指令 bg1 结束」），随即睡下——不发请求，签上写「等后台」，仍算在做（帮手条里挂着它、「止」照样叫停它）。指令结束的消息寄给帮手自己，落在它自己的时间线里（一步「回报 · 后台 bg1 已结束」），它醒来据输出接着做，做完再交一次差；主对话这边先后收到进展与回报两份。于是一件长活可以整段交给一名帮手：开训练 → 睡 → 醒来评估 → 不满意再开一轮 → 交差，主模型全程不必盯着。先交进展而不是攒着，是为了主模型不干等、也不会被一条忘了停的开发服务器挂住（帮手的系统提示里有一句：不必等的收工前结束它）。等的指令随桥接重启而止，帮手醒来见没有信就此收工，进展即它最后的话，不再重报；主模型经 `helper` 递话照样叫醒它。页面刷新时睡着的帮手与做着的一样随之中断。

主模型可用 `helper` 按差遣时起的任务名给帮手递话。正做着的，话进它自己的收件口，与用户的补言同一套：它正说着就等到句尾再停这一轮递上，正跑工具就等结果交回时递，不掐断；这句话落在帮手自己的时间线里（一步「传话」，递到打勾）。已收工的即**续派**：同一名帮手带着先前的经过接着做——它记得自己上一趟领的命、交的回报与行迹，回报照样寄回。叫停只停正做着的那一名，主答照常；它已做的照「未完成」回报送到，写明是按吩咐叫停。递话、续派、叫停在主行迹里也各是一枚金签：续派与传话的签标「已更新」，点开即那名帮手——续派开的是新的这一趟（面板顶上「所领之命」即新交代的活，‹ › 可翻回它的上一趟），传话开到递去的那句话。

长活不会因上下文满了而白做：一答（主答、旁注、每名帮手各自）之内的工具往来叠到快撑破窗口时，先请模型把较早的往来压成一份「工作笔记」（查明的事实、改过的文件、验证与否、走不通的路、下一步），代替原文接着做，最近两轮原样留着；这一答之前的对话与帮手的任务说明不动；若放不下的正是这一答之前的对话，主答会先把它压成摘要（与「压缩前文」同一份，落成分隔），旁注与帮手不压。填了模型的「上下文窗口」，送出前估到七成半就压；没填，接口回说放不下时压了再发一回。页面上的步骤一步不少，只是送给模型的少了；帮手压过的，签上记「压缩 n 回」。两答之间的「压缩前文」照旧，见[对谈](chat.md)。

## 稳定性边界与参数救治

稳定性边界：一次回答默认最多 80 轮工具调用（帮手另计，默认 40 轮），「设置 → 工具」可改，超出后收回工具、请模型直接收尾；停止生成、页面刷新或连接中断时，运行中与等待确认的步骤一并收束，正在跑的指令连同它起的子进程整棵一起被桥接杀掉（`taskkill /T`），不会在后台继续改文件；每次发送前确认桥接在线与工作目录仍在（被删除时自动重建）。

工具参数按 `prompts/tools.js` 里的 schema 理顺（`src/15-tools/01-arguments.js`）：常见的写法出入自动归位（`file_path` → `path`、`cmd` → `command` 之类的别名，数字与布尔写成了字符串，该是数组的只给了一项，`ask_user` 把单个问题摊在顶层），理顺后仍缺必填项的才不执行，并把收到的键与原文回给模型。模型输出被最大长度截断时，参数 JSON 会被尽量补齐——只读工具（读、列、搜、检索）照用，有副作用的（`run_command` / `write_file` / `edit_file` / `download_file` / `http_request` / `remember` / `forget` / `delegate`）一律拒绝并告诉模型原因，不会把截掉了 `content` 的 `write_file` 当成空文件写下去。同一答里相同参数的检索、翻阅、计算与请示复用已有结果，但只缓存成功的，临时的超时与报错不会被复用。

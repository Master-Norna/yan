# 录 · 记忆

[← 文档目录](README.md) · [English](en/memory.md)

- 记忆是关于你的话（偏好、身份、约定、进行中的事），按类各成一份全文，跨对话都带着。开关在设置的「专司」里：给「记忆优化」配一份接口与模型，配好了才带、才记；关掉即不带不记，记忆仍在
- 两层：这里说的是跨对话的一层，关于你本人、处处成立的；只在某个目录成立的，执事记在那个目录的 `.yan/记忆.md`，在那里每一问都附着，不经专司、不受这里的开关管（见[言与行 · 记忆](work.md#记忆)）
- 带进对话：整份记忆放进系统提示，一类一段，模型不必去翻。这段对话第一次拼进系统提示时定格（打开即定格，刷新页面后重新定格），此后记的、理过的都不改它，系统提示不变，前面的缓存接得上。记多少不设上限
- 记：主模型用 `remember` 写一类改后的全文——仍成立的照留，新的并进去，过时的、你要它忘的删去；写空即删去这一类。行迹里写作「记入」。一类一份而非一条一事：一条条记时模型多半另起一条、不去改旧的，越记越碎；一类一份，要记就得把那一类整份写过，旧的自然并进去。只给主模型，旁注只读得到记忆，帮手不带
- 优化：记忆改过之后（模型记的、你在设置里改的），一答落定时专司「记忆优化」理一遍——合并重复、改掉矛盾、删去只关一时的细节与空话，只答回要改的那几类的全文，没提到的一字不动。它只读记忆本身，不读对话，所以只在记忆真改过时花墨；整理期间记忆有变动或换了存储位置，这批结果不写入并提示，留到下一答按最新内容再理，避免并类、改类名把旧内容带回来。理过几类，提示一句；花的墨记进用量卡的「记忆」
- 旧对话：`search_conversations` 按关键词查（不给关键词即按时间列出最近的），`read_conversation` 分段读一段的主线；这两件常给，与记忆开不开无关。读过的列在回复底部的「出处」里，点开即回那一段
- 设置页「记忆」一栏：左列各类，右边是选中那一类的全文，点一下即改，改空即删去这一类；类名就地可改，改作已有之名即并为一类。记忆随备份导出，导入时同名一类的全文接上去、已有的行不重接。旧版一条一事的记忆，读入时同类几条并成一份

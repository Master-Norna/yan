# 内置提示词

模型能看到、而用户在界面上看不到的文字，都收在这一目录里，改完刷新页面即生效（无需重启桥接）。

| 文件 | 内容 | 何时进入请求 |
| --- | --- | --- |
| `assistant.js` | 通用系统提示：日期、联网、画图约定、言的答法（manner）；自动拟题；压缩前文的摘要请求，与摘要进历史时的一问一答；一答之内压工具往来的工作笔记请求（fold / folded）；作答途中插进对话的几句（断线续写、工具轮次到顶、补言前缀、用户没批这一步）；文末的 `order` 是系统提示的拼接次序表 | 每次请求；各段照 `order` 表按条件拼接（拟题与压缩是单独的请求；插话随时机进历史） |
| `work.js` | `role` + `hint`：「行 · 执事」的身份（只给主答）、环境与收尾；`archive` + `deliver`：言里工具落在卷宗时的一段轻提示（草稿目录、成品放根；成品由页面列出这句只给主答）；未读先改时回给模型的话；`env`：沙箱环境备好时的一句（装了什么、缺的往哪装） | 绑了目录用 hint，没绑用 archive |
| `side.js` | 旁注追问的聚焦句 | 仅旁注面板里的请求 |
| `memory.js` | 录（记忆）：有这回事、有多少条 | 记忆启用时；条目内容本身不进提示 |
| `delegate.js` | 差遣（子 Agent）：帮手自己的系统提示；回报的格式 | 帮手的请求另拼一段 |
| `graph.js` | 纲：验的人的系统提示（`audit`）与它领到的那份说明；验完回给做的人的一行；收尾的闸递的话 | 验的人的请求另拼一段；判词与闸的话作为工具结果、用户消息进历史 |
| `mcp.js` | 接入的 MCP 服务自带的用法（接在系统提示末尾）；工具不存在、参数不合时回给模型的话 | 有 MCP 工具交给模型时 |
| `tools.js` | 各工具的 description 与参数说明；带 `brief` 的在言里用 brief（短说明） | 随工具一并交给模型；言不带 edit_file / search_files / update_graph；verdict 只给验的人；旁注不带 http_request；run_js 谁都有 |

拼接顺序（系统提示）：预设的提示词（对话选了预设时）在最前，其后照 `assistant.js` 文末的 `order` 表逐段拼。表里一段一行，写明何时带上：`tool` 是交给模型的工具里有这一件才带，`mode` 是只给行（work）或只给言（chat），`roles` 是只给主答（main）、旁注（side）、帮手（sub）或验的人（audit）。要填值、或视情形不带的（环境没备好、没有 MCP 服务附用法、旁注注的是一段还是整条），由 `src/14-chat-engine/50-prompt.js` 的 `PROMPT_VARS` 给出，给 `null` 即这回不带。`test/prompt-size.mjs` 用页面同一份代码拼（默认档：沙箱开、问而后行），量出来的与模型实际读到的一致，加一段只需在表里添一行。

留哪句：先问「不写这句，模型是否做不到、或会误会」。该写的是它无从自知的事实（日期、目录、有哪些工具与 MCP、页面怎么呈现），以及不说便可能被当成强制的能力（有需要才用工具、帮手、内联可视化）。性格训诫（有己见、不奉承）、写了只图安心的叮嘱、结构已经解决的事（补言的先后由历史次序交代，不靠一句「以后说的为准」）都不写：弱模型不因此变好，强模型不说也做得好，多出的字只稀释注意。
口吻：少数句子调的是权重而非功能（答得短些、收尾交代几句）。写成命令或考核便成了收敛压力，模型易为守规矩陷入局部最优；写成「可」「即可」「不必」，以事实代禁令（「链接由页面给出」而非「勿自造链接」），给它一种可能，不催不迫。拟题、压缩这类一次性的抽取请求例外：输出格式本身就是功能。
行文文白相杂、能省则省：今日能接工具的模型读「便」「亦」「者」不费力，省下的字都是每一问的开销，顺带让它答得也雅一点；但不用生僻的文言，读不懂或读歪了就得不偿失。改提示词后跑 `node test/prompt-size.mjs` 看言那一行有没有涨回去。

分工原则：模型是把系统提示和工具定义一起读的，同一件事只说一遍——每件工具做什么、何时用、有什么不能猜的规矩，写在 `tools.js` 的 description 里；系统提示只放环境事实（日期、目录、平台、shell）和页面的呈现约定（画图、成品列表）。改提示词后跑 `node test/prompt-size.mjs` 看各模式的总量（`--dump` 打印模型读到的全文），再跑 `npm test` 过一遍用例。

写法：每个文件往 `window.YAN_PROMPTS` 挂一个对象（桥接拼 `/support.js` 时把本目录的 `.js` 排在最前，新添一份放进来即可），值是字符串或按行拼接的字符串数组；`{{名字}}` 是运行时填入的值，名字见各文件注释。系统提示的装配在 `src/14-chat-engine/50-prompt.js` 的 `systemPrompt`；哪件工具在何处给出、帮手与旁注能不能用，登记在 `src/15-tools/` 的注册表里（`toolDefinitions` 据此挑出并填好说明）。两处都只做拼接，不含文案。

未收入此处、但模型同样会看到的：历史消息的改写（引用以 `>` 引出、执事的「［上一答的行迹］」摘要（冠在下一问开头）、附件超长时的摘要标头，见 `src/14-chat-engine/00-history.js` 的 `quotedText` / `stepsDigest` / `attachmentExcerpt`），以及桥接抛出的工具错误（`server/work/index.js`，如「未找到要替换的文本」）——它们是数据格式与运行时反馈，随代码走。
